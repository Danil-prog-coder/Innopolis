# Стек tg_bot

| Технология | Назначение |
|------------|------------|
| **aiogram 3** | Telegram-бот: команды, кнопки, пошаговые диалоги (FSM) |
| **PostgreSQL** | Основное хранилище: пользователи, проекты, членство и роли, приглашения, хеш пароля проекта, вопросы без ответа |
| **Tortoise ORM** | Асинхронная работа с PostgreSQL (через asyncpg) |
| **Aerich** | Миграции схемы базы данных для Tortoise ORM |
| **Redis** | Состояния пошаговых диалогов (`RedisStorage` aiogram), кэш, ограничение частоты запросов |
| **Pydantic** | Настройки из `.env` (`pydantic-settings`) и модели обмена данными с LLM-сервисом |
| **httpx** | Запросы к LLM-сервису |
| **argon2** | Хеширование секретного пароля проекта |
| **pytest + pytest-asyncio** | Тесты |
| **ruff** | Линтер и форматирование |
| **uv** | Управление зависимостями |
| **Docker Compose** | Локальный запуск бота, PostgreSQL и Redis одной командой |

## Фоновые задачи

Удаление сообщения с паролем и рассылка уведомлений участникам проекта (с учётом лимитов Telegram) на старте делаются на asyncio. Позже их стоит перенести в очередь задач поверх Redis (taskiq или arq), чтобы они не терялись при перезапуске бота.
