# Корпоративный Telegram-бот

Проект от компании **БАРС Груп** в рамках программы Иннополиса.

## О проекте

Умный Telegram-бот, который мгновенно отвечает на вопросы пользователей на естественном языке, опираясь исключительно на актуальную документацию проекта.

Бот не придумывает ответы сам: он находит в базе документации фрагменты, относящиеся к вопросу, и формирует ответ только на их основе (подход RAG — Retrieval-Augmented Generation).

## Основные возможности

- Ответы на вопросы пользователей на естественном языке прямо в Telegram
- Поиск релевантной информации по документации проекта
- Ответы строго по актуальной документации, без выдуманных фактов
- Быстрая работа за счёт кэширования

## Features

### Вопрос без ответа уходит админу

Обычный RAG-бот, не найдя ответа в документации, говорит «не знаю», и на этом всё заканчивается. Наш бот превращает такой вопрос в задачу для админа проекта: пересылает вопрос, админ отвечает, ответ доходит до сотрудника и может быть сохранён в базу знаний.

- Сотрудник получает ответ, даже если в документации его нет.
- Документация пополняется из реальных вопросов сотрудников, а не по догадкам.
- Бот по-прежнему ничего не выдумывает: новое знание попадает в базу только после проверки человеком.
- Админ видит, каких тем в документации не хватает.

### Вопрос скриншотом

Вместо того чтобы описывать проблему словами, сотрудник присылает скриншот ошибки или экрана системы.

- Не нужно подбирать формулировку вопроса.
- Точные тексты ошибок и названия полей берутся прямо с экрана, без опечаток и пересказа.

### Уведомления об обновлении документации

При каждом обновлении документации все участники проекта получают уведомление, а по кнопке — краткую сводку изменений.

- Сотрудники узнают об изменениях сразу, а не когда случайно на них наткнутся.
- Сводка экономит время: не нужно перечитывать документацию, чтобы понять, что поменялось.

### Бот в рабочем чате команды

Бота можно добавить в групповой чат команды и задавать ему вопросы прямо там.

- Ответ видят все участники чата, поэтому одно и то же не переспрашивают.
- Не нужно уходить из рабочего чата в личную переписку с ботом.
- Бот видит только обращённые к нему сообщения и не читает остальную переписку команды (privacy mode Telegram).

### Секретный пароль админа

При создании проекта его создатель получает уникальный секретный пароль. Пароль не остаётся в истории переписки. Он нужен, чтобы стать ещё одним админом проекта или полностью заменить документацию.

- Опасные действия защищены: даже имея доступ к аккаунту админа, без пароля нельзя стереть документацию.
- Создатель сам решает, кому дать права админа, — просто передаёт пароль.

### Несколько проектов у одного человека

Пользователь и админ могут состоять сразу в нескольких проектах и переключаться между ними. Бот всегда показывает, в каком проекте человек сейчас и с какой ролью.

- Сотрудник, работающий на нескольких проектах, обходится одним ботом.
- Вопрос всегда уходит в документацию нужного проекта, и человек это видит.

## Стек технологий

| Технология | Назначение |
|------------|------------|
| **Python** | Основной язык разработки |
| **FastAPI** | Backend-сервис и API |
| **OpenAI** | Эмбеддинги и генерация ответов |
| **Qdrant** | Векторная база данных для поиска по документации |
| **Redis** | Кэширование и хранение состояния диалогов |

## Как это работает

1. Документация проекта разбивается на фрагменты, для каждого строится эмбеддинг, всё сохраняется в Qdrant.
2. Пользователь задаёт вопрос боту в Telegram.
3. Вопрос превращается в эмбеддинг, и в Qdrant ищутся самые похожие фрагменты документации.
4. Найденные фрагменты вместе с вопросом передаются в модель OpenAI, которая формирует ответ.
5. Бот отправляет ответ пользователю. Частые запросы и контекст диалога хранятся в Redis.

## User Flows

> Черновик: уточнится, когда появится более конкретное ТЗ.

### Роли

При первом запуске бота (`/start`) пользователь выбирает роль:

- **Админ** — создаёт проекты, загружает документацию, управляет участниками.
- **Пользователь** — подключается к проекту и задаёт вопросы по его документации.

Выбор роли при входе — временное решение; порядок назначения админов пересмотрим по ТЗ.

### Админ

После выбора роли «админ» бот предлагает два варианта: **«Создать проект»** или **«Присоединиться к проекту в роли админа»**.

1. **Создание проекта.** Админ создаёт проект и задаёт ему название. Бот выдаёт создателю уникальный **секретный пароль** проекта так, чтобы он не остался в истории переписки (самоудаляющееся сообщение или всплывающее окно — см. «Открытые вопросы»).
2. **Присоединение в роли админа.** Человек выбирает «Присоединиться к проекту в роли админа» и вводит секретный пароль. Пароль может передать только создатель проекта.
3. **Загрузка документации.** Документация загружается прямо в боте. У админа две кнопки:
   - **«Дополнить документацию»** — новые файлы добавляются к уже загруженным;
   - **«Заменить документацию»** — после нажатия админ вводит секретный пароль, и документация проекта полностью заменяется новой.

   Документация индексируется и доступна для поиска только внутри этого проекта.
4. **Приглашение участников.** Админ создаёт ссылку-приглашение вида `t.me/<бот>?start=<код>` и раздаёт её команде. У ссылки есть срок действия (TTL), админ может отозвать её досрочно.
5. **Управление участниками.** Админ видит список участников проекта и может удалить любого (например, при увольнении). Удалённый участник теряет доступ к проекту.

### Пользователь

1. **Подключение к проекту.** Два способа:
   - **По ссылке.** Пользователь переходит по ссылке-приглашению, бот получает код из неё.
   - **Вставкой в чат.** Если пользователь не переходил по ссылке, он выбирает роль «пользователь» и просто вставляет скопированную ссылку (или сам код) в чат с ботом.

   В обоих случаях бот проверяет код (существует, не истёк, не отозван) и добавляет пользователя в проект.

### Работа внутри проекта

После того как админ создал проект или пользователь подключился к проекту, бот присылает сообщение, с которого начинается работа:

- можно сразу задать вопрос в свободной форме — обычным сообщением в чат;
- кнопка **«Инструкция, как добавить бота в ваш чат»**;
- кнопка **«Присоединиться к другому проекту»**.

Над полем ввода всегда видна кнопка с текущим проектом и ролью, например **«📁 Проект X · админ»**. По нажатию бот показывает список проектов человека, и в нём можно переключиться на другой.

Вопросы могут задавать и админ, и пользователь. Бэкенд передаёт в LLM-сервис пару «вопрос + id текущего проекта», поиск идёт только по документации этого проекта, и бот отправляет ответ в чат.

### Сценарии

#### Вопрос, которого нет в документации

Представим, пользователь задал вопрос, ответа на который в документации проекта нет.

1. Бот отвечает пользователю, что в документации ответа нет и вопрос передан админу.
2. Бот пишет админу проекта: «Мне задали вопрос X, однако в документации ответа нет. Ответьте сами или дополните документацию».
3. Если админ отвечает, бот пересылает ответ пользователю и предлагает админу сохранить его в базу знаний проекта. Тогда на такой же вопрос в следующий раз бот ответит сам.
4. Если админ дополняет документацию, запускается сценарий «Обновление документации».

#### Вопрос скриншотом

Представим, у пользователя на экране ошибка, и он не знает, как её описать.

1. Пользователь присылает боту скриншот, при желании с подписью.
2. Бэкенд передаёт изображение вместе с id проекта в LLM-сервис.
3. Бот отвечает по документации, как на обычный вопрос. Если ответа нет, запускается сценарий «Вопрос, которого нет в документации».

#### Обновление документации

Представим, админ дополнил или заменил документацию проекта.

1. Если админ нажал «Заменить документацию», бот сначала запрашивает секретный пароль. При «Дополнить документацию» пароль не нужен.
2. Документация переиндексируется.
3. Все участники проекта получают уведомление «Документация проекта обновлена» с кнопкой **«Что изменилось»**.
4. По нажатию кнопки бот присылает краткую сводку изменений.

#### Ещё один админ в проекте

Представим, создателю проекта нужен помощник с правами админа.

1. Создатель передаёт помощнику секретный пароль проекта.
2. Помощник запускает бота, выбирает «Админ» → «Присоединиться к проекту в роли админа» и вводит пароль.
3. Бот проверяет пароль и добавляет помощника в проект как админа.

#### Переход в другой проект

Представим, сотрудник уже состоит в одном проекте, а его подключают ещё к одному.

1. Пользователь нажимает **«Присоединиться к другому проекту»**.
2. Дальше всё как при первом подключении: пользователь переходит по ссылке-приглашению или вставляет код, админ — вводит секретный пароль.
3. Бот добавляет человека в новый проект, старые проекты сохраняются.
4. Новый проект становится текущим, и кнопка над полем ввода обновляется: «📁 <новый проект> · <роль>».

#### Вопрос в рабочем чате команды

Представим, команда обсуждает задачу в своём групповом чате, и появился вопрос по документации.

1. Участник проекта открывает в личном чате с ботом «Инструкцию, как добавить бота в ваш чат» и по ней добавляет бота в групповой чат.
2. Любой участник чата привязывает чат к проекту: отправляет команду `/join@имя_бота <код>` с кодом доступа к проекту (тем же, что в ссылке-приглашении).
3. Участники чата задают вопрос командой `/ask@имя_бота <вопрос>` или упоминанием `@имя_бота <вопрос>`.
4. Бот отвечает в групповой чат, ответ видят все.

### Изоляция проектов

Пользователь никогда не получает ответ по документации чужого проекта: каждый запрос к LLM-сервису содержит id проекта, и поиск ограничен им.

### Открытые вопросы

- Как выдать секретный пароль: самоудаляющимся сообщением или всплывающим окном.
- Бот может скачать файл не больше 20 МБ: как быть с большими файлами документации.
